# GEMINI.MD: AI Collaboration Guide

This document provides essential context for AI models interacting with this project. Adhering to these guidelines will ensure consistency and maintain code quality.

## 1. Project Overview & Purpose

*   **Primary Goal:** ORDERFLOW is an AI-powered restaurant order management system. It processes customer SMS messages (via Twilio), automatically detects orders using AI, and provides a real-time web dashboard for restaurant managers to track orders, manage menus, and communicate with customers.
*   **Business Domain:** Restaurant Technology / Food Service (Order Management System).
*   **Key Features:** SMS-based ordering, AI order parsing/detection, real-time dashboard updates (SSE), menu management, and Clover POS integration.

## 2. Core Technologies & Stack

*   **Languages:** TypeScript (Primary), SQL.
*   **Frameworks & Runtimes:**
    *   **Runtime:** Node.js (v18+).
    *   **Backend:** Express.js.
    *   **Frontend:** React (v18) with Vite.
    *   **Styling:** Tailwind CSS, Radix UI.
*   **Databases:**
    *   **Primary:** PostgreSQL.
    *   **ORM:** Drizzle ORM.
    *   **Caching/Queues:** Redis (optional, for production SSE/Scaling).
*   **Key Libraries/Dependencies:**
    *   **Validation:** Zod (shared schemas via `drizzle-zod`).
    *   **AI:** OpenAI SDK (supports OpenAI & Trucube models).
    *   **Auth:** Passport.js (Local Strategy), `express-session`, `connect-pg-simple`.
    *   **External APIs:** Twilio (SMS), Clover (POS).
    *   **Routing (Frontend):** Wouter.
    *   **State/Query:** TanStack Query (React Query).
*   **Package Manager:** `npm`.

## 3. Architectural Patterns

*   **Overall Architecture:** Monorepo-style Full Stack Application.
    *   The project serves a React frontend via Vite (proxying API requests) and runs an Express.js backend API.
    *   **Data Flow:** Client <-> API (Express) <-> Service Layer <-> Drizzle ORM <-> PostgreSQL.
    *   **Real-time:** Server-Sent Events (SSE) push updates from backend to frontend.
*   **Directory Structure Philosophy:**
    *   `/client`: Contains the React frontend application.
    *   `/server`: Contains the Express backend application.
        *   `/server/controllers`: Request handlers.
        *   `/server/services`: Business logic (AI processing, DB interactions).
        *   `/server/routes`: API Route definitions.
    *   `/shared`: Contains code shared between client and server, primarily Drizzle schemas and Zod types (`schema.ts`).
    *   `/migrations`: Database migration files generated by Drizzle Kit.

## 4. Coding Conventions & Style Guide

*   **Formatting:**
    *   Indent with 2 spaces.
    *   Semicolons are used.
    *   Double quotes preferred for strings in imports/JSON, single quotes often used in code (follow existing file context).
*   **Naming Conventions:**
    *   **Variables/Functions:** camelCase (e.g., `analyzeOrderSummary`, `menuItems`).
    *   **Components:** PascalCase (e.g., `OrderCard`, `MessageBubble`).
    *   **Files:**
        *   React Components: PascalCase (e.g., `OrderCard.tsx`).
        *   Utilities/Services: camelCase/kebab-case (e.g., `aiFunctions.ts`, `utils.ts`).
    *   **Database:** snake_case for column names in SQL, mapped to camelCase in application code via Drizzle (e.g., `pickup_time` -> `pickupTime`).
*   **API Design:**
    *   RESTful API.
    *   JSON request/response bodies.
    *   Prefix: `/api/...` (inferred from usage).
*   **Error Handling:**
    *   Express error handling middleware is set up in `server/index.ts`.
    *   Async/await with `try...catch` blocks in services/controllers.
*   **Type Safety:**
    *   **Strict:** Heavy reliance on shared Zod schemas (`/shared/schema.ts`) to ensure type consistency between Database, API, and Frontend. Always prefer using these shared types over defining `any`.

## 5. Key Files & Entrypoints

*   **Main Entrypoint (Server):** `server/index.ts` - Sets up Express, Middleware, Routes, and Vite (dev mode).
*   **Main Entrypoint (Client):** `client/src/main.tsx` - Bootstraps React app.
*   **Database Schema:** `shared/schema.ts` - **CRITICAL FILE**. Defines DB tables, relations, and Zod schemas. Modifications here affect both client and server.
*   **Configuration:**
    *   `.env`: Environment variables (API Keys, DB URL).
    *   `drizzle.config.ts`: Drizzle Kit configuration.
    *   `vite.config.ts`: Vite build configuration.
*   **AI Logic:** `server/aiFunctions.ts` - Contains the core logic for order parsing and response generation.

## 6. Development & Testing Workflow

*   **Local Development Environment:**
    *   Command: `npm run dev` (Starts backend with `tsx` and frontend via Vite).
    *   Database Push: `npm run db:push` (Syncs schema changes to DB).
    *   Migrations: `npm run migrate`.
*   **Testing:**
    *   No explicit test framework configuration observed in root (e.g., Jest/Vitest config), but standard `npm test` script may exist (check package.json).
*   **Deployment:**
    *   Build: `npm run build` (builds client and server).
    *   Start: `npm start` (runs `dist/index.js`).

## 7. Specific Instructions for AI Collaboration

*   **Shared Schema Awareness:** When modifying the database schema (`shared/schema.ts`), YOU MUST be aware that this affects both the backend (Drizzle models) and the frontend (Zod validation types). Always update both sides if breaking changes are made.
*   **Environment Variables:** Do not hardcode API keys (OpenAI, Twilio). Use `process.env`.
*   **AI Prompts:** Prompt engineering logic is located in `server/utils.ts` or `server/aiFunctions.ts`. When tweaking AI behavior, modify the system prompts there.
*   **Design System:** The project follows a specific design guideline ("Corn on the Corner") leveraging Tailwind CSS and Radix UI. Ensure new UI components match the "iMessage-style" customer view or the "Dashboard" productivity view described in `design_guidelines.md`.
*   **Dependencies:** Use `npm` for package management.
